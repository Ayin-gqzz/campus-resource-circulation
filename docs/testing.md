# 测试计划

Maven 使用 JUnit 5 和 Surefire，GitHub Actions 执行 `mvn clean verify`。数据层由仓储集成测试覆盖。Demo 集成测试走同一套 JDBC 仓储，覆盖发布、意向、交接、互评、权限校验、取消后重新流转及重开数据库后的持久化。

交易地点测试覆盖发布必填、流转记录中的地点留存，以及版本 1 演示库升级后由发布人补填地点并继续交易。

| 数据集成测试 | 已覆盖临时 SQLite 初始化、外键和唯一约束、事务回滚（见下）。待补充并发写与数据备份恢复 |

## 数据层集成测试

三个测试类位于 `src/test/java/edu/campus/circulation/repository`，均在 `@TempDir` 下创建临时 SQLite 库，每个用例先调用 `DatabaseManager.initialize()` 建库，不触碰成员的真实数据库，也不依赖库中已有数据。执行命令为 `mvn test`，当前共 49 个用例（含参数化展开）。

| 测试类 | 用例数 | 覆盖范围 |
| --- | --- | --- |
| `UserAndCategoryRepositoryTest` | 25 | 初始化与版本检查、连接 PRAGMA、事务与回滚、时间格式、异常转换、用户与分类仓储 |
| `ItemRepositoryTest` | 12 | 物品发布、字段组合 CHECK、编辑与状态、组合检索、收藏 |
| `ExchangeAndReviewRepositoryTest` | 12 | 意向与首条留言、留言、接受 / 完成 / 取消流转、评价与信用、分类统计 |

### 初始化、连接与事务（UserAndCategoryRepositoryTest）

- 从 classpath 载入脚本，`user_version = 2`、9 张表。重复初始化时保留已有数据。
- `user_version` 为 3 或 99 时抛出 `DataAccessException`，版本值不被改写。
- 库中已存在同名 `categories` 表导致建表中途失败时整体回滚，`user_version` 仍为 0 且没有 `users` 表。
- 普通连接与事务连接都满足 `PRAGMA foreign_keys = 1`、`PRAGMA busy_timeout = 5000`，外键违例抛 `ForeignKeyException`。
- `inWriteTransaction` 在执行工作前已取得写锁：另一连接关闭 busy_timeout 后写入返回错误码 5。
- 事务连接绑定当前线程：嵌套事务复用同一连接且不提前提交，子线程取不到该连接；运行时异常与 `Error` 都回滚，转换后的唯一约束失败同样整体回滚。
- `UtcTimestamps` 输出固定毫秒格式、截断纳秒、拒绝 `2026-02-30` 这类非法日期；`SqlExceptions` 覆盖扩展码 2067 / 1555 / 787 与错误码 19 的消息文本判断。
- 用户：全字段映射、按用户名不分大小写查询、重复用户名保留原账号、用户名与角色 CHECK、停用与恢复。
- 分类：可空系数、名称唯一、系数与来源成对及非负与长度约束、启用过滤。

### 物品（ItemRepositoryTest）

- 发布售卖与交换物品，状态固定为 `AVAILABLE`，标签去空白并按大小写去重，读取时按标签名排序。
- 字段组合 CHECK（售卖缺价格、售卖价格为零、售卖带交换说明、交换带价格或缺说明、交换说明为空白）与超长、空标签被拒绝。
- 编辑按预期状态生效并整体替换标签，非法标签使物品行一并回滚；`updateStatus` 在旧状态不符或 ID 不存在时返回 `false`。
- 检索按分类、标题或描述关键词、价格区间组合过滤；关键词不分大小写，`%`、`_` 与 `\` 被转义为字面量。
- 指定价格区间只返回售卖物品且边界包含；结果只含在架且发布人启用的物品，发布人恢复启用后重新出现。
- 收藏重复写入只保留一条，可删除，删除不存在的收藏返回 `false`；用户或物品不存在时抛 `ForeignKeyException`。

### 意向、流转与评价（ExchangeAndReviewRepositoryTest）

- 提交意向与首条留言在同一写事务内完成，留言为空或超长时两者都不留下；同一用户对同一物品的重复待处理意向被部分唯一索引拒绝；留言按记录 ID 而非发送时间排序。
- 在外层 `inWriteTransaction` 中提交意向，外层回滚时意向与留言一起消失，说明仓储不提前提交。
- 接受意向后目标进入 `ACCEPTED`、同物品其他 `PENDING` 进入 `REJECTED`、物品 `AVAILABLE → RESERVED`，其他物品不受影响；物品更新失败时整体回滚。
- 每件物品最多一个 `ACCEPTED` 或 `COMPLETED` 意向，违反时抛 `UniqueConstraintException`。
- 完成操作要求预期旧状态，写入完成时间并同步物品为 `COMPLETED`；完成时间为空、早于创建时间或非完成状态却带完成时间都被 CHECK 拒绝并保持原状态，预期旧状态不符或 ID 不存在时返回 `false`。
- `cancelPendingByUser` / `cancelPendingByItem` 只影响 `PENDING` 并返回受影响行数，已接受与已拒绝的意向不变。
- 评价星级 1–5、评论长度、禁止自评由 CHECK 拦截；同一评价人重复评价被主键拒绝；流转或用户不存在抛 `ForeignKeyException`；双方各一条记录按创建时间排序。
- 信用汇总的平均星级保留一位小数，无评价时平均值为 `null`、条数为 0。
- 分类统计只计 `COMPLETED`，完成时间使用左闭右开区间，可按参与人和分类过滤；停用分类仍显示原名与系数，系数缺失返回 `null`，系数为 0 时保留 0。

### 与需求的对应

| 需求 | 数据层已验证的部分 |
| --- | --- |
| R01 账号 | 用户名规则与大小写唯一、角色枚举、启用状态；密码哈希仅作为普通列存取 |
| R02 发布 | 售卖 / 交换字段组合、标签规范化、发布人按预期状态编辑 |
| R03 检索与收藏 | 组合筛选、价格区间只对售卖生效、隐藏停用发布人、收藏去重 |
| R04 意向与流转 | 待处理唯一、每物品唯一成功流转、接受时拒绝其他意向并锁定物品、批量拒绝与取消、参与者历史 |
| R05 评价与信用 | 每方一次、星级范围、平均值保留一位小数 |
| R06 统计与导出 | 完成时间半开区间、分类与参与人过滤、系数缺失只计数量 |
| R07 管理 | 分类启用过滤与历史系数保留、账号停用后物品从检索隐藏；停用连带取消意向由服务层组合仓储方法完成 |
| R08 质量 | 多表写操作在同一事务提交、失败整体回滚、SQL 异常按唯一 / 外键 / 其他分类 |

跨表权限规则由服务层校验。Demo 集成测试已覆盖禁止对本人发布的物品提交意向、请求方不能接受意向、禁止提前及重复评价。正式账号、后续留言与管理权限留待对应业务服务实现时补测。
