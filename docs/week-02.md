## 可复验的 Demo 验收

执行 `mvn clean verify` 后运行 Jar。演示可以指定一个新的 `campus.demo.db` 路径获得初始样例，原演示库可直接打开。

| 场景 | 验收步骤与预期 |
| --- | --- |
| 售卖、权限与互评 | 陈同学对高等数学教材发起意向，重复提交应被拒绝。切换为林同学接受，教材应退出集市。确认交接后双方各评一次，评分应分别显示在对方身份中 |
| 换物取消 | 陈同学对 USB 台灯发起意向，林同学接受。任一参与者取消后，原意向保留为「已取消」，台灯重新在架，可以再次发起意向 |
| 数据留存 | 关闭并用同一个数据库重新打开应用，检查意向、物品状态和星级。新库只生成两位示例身份和三件示例物品 |
| 数据约束 | 仓储测试检查外键、唯一约束、字段限制、事务回滚、分类与价格筛选，以及按分类统计等规则 |

当前验收范围是设计材料、JDBC 数据层和可演示的流转流程。正式注册登录、物品编辑与下架界面、管理后台和报表导出按后续迭代继续实现。

2026 年 11 月 12 日在 Windows 和 JDK 21 环境执行 `mvn clean verify`，49 个仓储集成测试与 2 个 Demo 集成测试全部通过。4 张 Mermaid UML 图均通过语法检查。用上一版 Jar 生成演示库并加入一条已完成流转后，新 Jar 能启动并读出原留言、星级和完成状态。两个调用并发打开同一个新库时，各自都读到同一批 3 件样例物品。
