# 实验要求与交付清单

本清单整理自《2026软件构造分组实验v3》中的课程要求。当前所有待办均未验收；初始化工程不等于实现了相关功能。Java 17、包结构及具体设计模式选型为本仓库的起步方案，并非文档指定版本或方案。

## 必须满足的约束

- [ ] Java 桌面应用，Swing / WindowsBuilder 事件驱动 GUI。
- [ ] SQLite + JDBC 持久化全部业务数据，包含事务处理。
- [ ] Maven 完整源码工程，可独立部署运行的可执行 Jar。
- [ ] 3 人协作、8 周增量开发，每 2 周输出版本。
- [ ] UML 类图和时序图，与最终代码对应。
- [ ] JUnit 单元测试、集成测试、回归测试、代码走查及静态分析。
- [ ] 恰当使用至少 3 种设计模式，说明解决的问题。
- [ ] 留存函数级和类级重构的前后对比与验证记录。
- [ ] 体现防御性编程、异常处理、日志、可维护性和可扩展性。
- [ ] 覆盖模块化、面向对象、文件 IO / CSV、GUI、数据库、复用、测试、重构与交付等课程章节；不能只完成简单 CRUD。

## 核心功能

| 模块 | 验收范围 |
| --- | --- |
| 账号与权限 | 注册、登录、安全存储密码、普通学生 / 管理员角色、输入合法性校验 |
| 物品管理 | 名称、分类、描述、交换意向 / 售价、状态、标签；修改和下架自己的物品 |
| 检索与收藏 | 分类、关键词、价格区间筛选，模糊查询、列表展示、收藏 |
| 沟通与流转 | 发起意向沟通、生成流转记录、成交 / 交换状态、历史持久化 |
| 评价与信用 | 完成流转后双方互评、维护和展示信用分数 |
| 统计与导出 | 分类流转数量、低碳减排估算、统计报表、CSV 导出 |
| 管理员后台 | 用户管理、违规物品下架、类别维护、平台流转统计 |
| 图形界面 | 菜单、弹窗、表格、事件响应，以及完整业务流程操作 |

## 第一周需求规格

系统在单机桌面运行。学生在同一应用和本地数据库中切换账号，完成发布、沟通和流转。售卖的付款和换物交接在线下完成。管理员账号通过受控的本地初始化流程创建。学生自行注册时只能获得学生角色。

| 编号 | 场景与验收条件 |
| --- | --- |
| R01 账号 | 用户名由 3–24 个英文字母、数字或下划线组成，大小写视为相同。注册重复用户名时保留原账号。登录错误或账号停用时不给予会话，密码通过带独立随机盐的密码哈希保存。 |
| R02 发布 | 学生使用启用的分类填写名称、描述、成色和标签，并选择售卖或交换。售卖填写大于零的价格，按整数分存储。交换填写期望换物说明。只有发布人能编辑自己的在架物品。存在待处理意向时锁定编辑，发布人可下架并关闭待处理意向。 |
| R03 检索与收藏 | 学生可组合分类、标题或描述关键词、价格区间筛选。搜索结果只显示在架且发布人启用的物品。指定价格区间时只返回售卖物品，边界包含在结果中。重复收藏同一物品只产生一条记录。 |
| R04 意向与流转 | 非发布人可对在架物品提交意向并附留言。双方可以在待处理或已接受阶段留言。发布人接受一个意向后锁定物品并拒绝其他待处理意向。请求人可撤回自己的待处理意向。发布人可拒绝待处理意向，任一参与人可取消已接受意向。双方在线下完成交接后由发布人确认完成。双方可查看自己的历史。 |
| R05 评价与信用 | 已完成流转的双方可各提交一次 1–5 星评价，可附短评。系统按收到的有效评价计算均值并保留一位小数，无评价显示“暂无评分”。第三方、重复评价和提前评价均应被拒绝。 |
| R06 统计与导出 | 按完成时间和分类统计已完成流转。学生看到本人参与记录的汇总，管理员查看全平台。估算量按分类成交数乘以单件系数计算，展示系数来源及未覆盖的记录数。CSV 使用 UTF-8，转义逗号、引号、换行，并处理文本字段的公式注入风险。导出使用与页面相同的筛选范围。 |
| R07 管理 | 管理员可停用或恢复学生账号、维护分类、下架违规物品。停用时结束该学生相关的待处理意向。有已接受流转时须先处理该流转，管理员可取消流转并下架物品。分类停用后禁止用于新发布或更换分类，历史记录保留。 |
| R08 质量 | Swing 提供表格、菜单和错误提示。耗时操作使用后台线程，界面在事件派发线程更新。一次操作涉及多张表时在一个事务中提交。日志记录关键操作和失败原因，密码与密码哈希不得进入日志。 |

统计只对有来源的系数给出估算值。截止时间使用半开区间，未完成或已取消的流转不计入。详细状态和写入规则见[系统架构](architecture.md)与[数据库设计](../database/README.md)。

## 可选扩展

- [ ] 本地备份与恢复。
- [ ] 关键操作日志增强。
- [ ] 复用开源库，支持本地图片存储。
- [ ] 改善交互体验。
- [ ] 基于浏览与购买 / 交换历史的简单推荐。

总体要求已包含日志与异常处理，选做“关键操作日志”不意味着可以省略基础日志。
