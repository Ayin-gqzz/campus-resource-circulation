# 8 周迭代计划

起止日期待小组确认。以下为相对周次；每轮完成演示、测试及文档同步后，再创建对应 Git 标签。

| 迭代 | 周次 | 目标 | 交付与验收 | 建议标签 |
| --- | --- | --- | --- | --- |
| 1 | 第 1–2 周 | 需求与设计 | 需求规格、模块接口、UML 类图 / 时序图、分工、数据库设计 | `v0.1.0` |
| 2 | 第 3–4 周 | 核心业务与单元测试 | 用户 / 物品业务、JDBC 数据层、基础持久化、JUnit 用例 | `v0.2.0` |
| 3 | 第 5–6 周 | GUI 与系统集成 | GUI、流转 / 评价 / 统计 / 管理功能串联、集成测试、缺陷修复 | `v0.3.0` |
| 4 | 第 7–8 周 | 重构与完整交付 | 重构记录、至少 3 种设计模式、系统测试、可执行 Jar、报告、使用说明、PPT / 视频 | `v1.0.0` |

每周至少记录一次组内讨论，包含本周实际进展、问题、接口变更、下周任务和责任人。不要提前把计划标签标为已发布版本。
